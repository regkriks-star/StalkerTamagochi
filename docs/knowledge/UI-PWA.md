# Интерфейс и PWA

**Сверено с кодом:** 20.11.2026.  
**Источник истины:** `src/App.tsx`, `src/style.css`, `src/MapViewport.tsx`,
`src/CharacterPortrait.tsx`, `index.html`, `vite.config.ts`,
`public/notification-handler.js`.

## 1. Экраны

Приложение — одна страница с четырьмя вкладками. Роутера нет: состояние
вкладки хранится в `useState`.

| Вкладка | id | Что показывает | Основные компоненты |
|---|---|---|---|
| Сталкер | `stalker` | Портрет, экипировка, уход, вылазка, смерть, фракция | `CharacterScene`, `CarePanel`, `RaidPanel`, `DeathPanel`, `FactionPanel` |
| Карта Зоны | `map` | Карта, точки, маршрут, диалог локации, могилы | `ZoneMap`, `MapViewport`, `RaidPanel` |
| Рюкзак | `bag` | Предметы, вес, использование, экипировка, продажа/оставление | `InventoryPanel` |
| Журнал | `journal` | Эфир (до 80 сообщений) и «Память Зоны» | `RadioFeed`, мемориал |

Общая рамка: `App` → `header.device-header`, `nav.navigation`,
`div.screen-content`, `footer.screen-footer`, `div.device-bottom`.

### Шапка

- Логотип «ЗОНА», модель ПДА–3М.
- Индикатор сети (`navigator.onLine`).
- Игровое время (`game.lastTick`).
- «Установить КПК» (PWA) и настройки.
- Статус сохранения в футере: «Прогресс сохранён…» / «Проблема с сохранением».

### Верхняя полоса статов

Пять `role="meter"`: здоровье, сытость, вода, силы, радиация. Показываются на
«Сталкер» и «Карте». Здоровье ограничено `maxHealth(game)`, остальные — 100.
Радиация инвертирована: опасность при > 40.

### Ключевые панели

- **Состояние**: кнопки «Накормить», «Напоить», «Подлечить», «Отдохнуть»,
  антирад, дедлайн ухода.
- **Портрет**: фон локации, тело, лицо/противогаз, костюм; слоты костюма,
  противогаза, основного и вторичного оружия; вес; имя; статус.
- **Вылазка**: фаза, прогресс, событие, таймер, варианты, подсказки.
- **Смерть**: причина, локация тела, кнопка нового сталкера.
- **Фракции**: список, репутация, бонусы, вступление, «остаться одиночкой»,
  «пусть решает сам».
- **Торговец**: баланс, покупка, продажа, ограничение веса.

## 2. Диалоги

Все окна — нативный `<dialog>` с `showModal()`:

- открытие в `useEffect`, закрытие при размонтировании;
- Escape — `onCancel` + `preventDefault`, закрывает через колбэк;
- клик по подложке закрывает, если `event.target === currentTarget`;
- `aria-labelledby="dialog-title"` и заголовок `h2`;
- кнопка «Закрыть окно» с `aria-label`.

Диалоги: создание персонажа, слот экипировки, локация, торговец, фракции,
настройки, «как играть», установка. Создание персонажа нельзя закрыть — у него
нет `close`.

**Известный дефект:** `id="dialog-title"` фиксированный. Если два диалога
окажутся смонтированы одновременно, получится дубль id и неверное имя
доступности. Пока это трудно достижимо, но лучше `useId()`.

## 3. Карта

`MapViewport` — собственный pan/pinch:

- `touch-action: none` на `.zone-map`;
- указатели запоминаются в `Map<pointerId, Point>`;
- drag одного пальца — сдвиг; двух — масштаб 1–3;
- порог 6px, чтобы тап не превращался в drag;
- после drag клик по точке подавляется в `onClickCapture`;
- кнопки зума: −, сброс (100%), +;
- маркеры компенсируют масштаб через `--map-marker-scale`.

`ZoneMap`:

- SVG-линия маршрута от текущей позиции/`startPosition` к цели;
- точки локаций — кнопки с `aria-label`, `aria-pressed`, замком по XP;
- маркер игрока;
- маркеры активных заданий (могилы, событие);
- диалог локации: опасность, время, находка, «Идти сюда» / «Изменить
  маршрут», «Осмотреть точку», «Забрать по вместимости», могилы;
- легенда и подсказка.

**Известные дефекты доступности:** `aria-label` на generic-`div` не
озвучивается; `aria-label` точки перекрывает название, XP-замок и число
заданий; `aria-pressed` семантически неточен для кнопки, открывающей диалог.
Панорамирование недоступно с клавиатуры.

## 4. Инвентарь и экипировка

- Фильтры: всё, припасы, артефакты, снаряжение.
- Карточка: спрайт, количество, «Надето», описание, действия.
- Действия: использовать, надеть/снять, на пояс/снять, оставить.
- Вес считается по всему инвентарю, включая надетое.
- Слоты: костюм, противогаз, основное оружие, вторичное оружие.
- Артефакт один; остальные лежат в контейнере.
- Продажа и оставление блокируются, если предмет «надет» (по типу, а не по
  конкретной копии).

## 5. Уведомления

### Поток

1. Пользователь нажимает «Включить уведомления» в настройках.
2. `Notification.requestPermission()` — только после явного действия.
3. Когда событие становится доступным (`phase=choice`, `openedAt=null`),
   эффект в `App` показывает системное уведомление через
   `ServiceWorkerRegistration.showNotification`, иначе fallback `new Notification`.
4. `tag: "zone-event"` — одно уведомление на событие.
5. Клик обрабатывает `public/notification-handler.js`:
   - закрывает уведомление;
   - ищет окно в scope;
   - если нашёл — `focus()` + `postMessage({type:"open-event", eventAt})`;
   - если нет — открывает `/?event=<startedAt>`.
6. `App` слушает `message` и `?event=`, вызывает `open-event`; reducer сверяет
   `eventAt` со `startedAt`, чтобы старое уведомление не открыло новое событие.
7. Когда событие открыто/закончилось, уведомление закрывается.

Если разрешение отклонено или API недоступен, событие остаётся внутри КПК:
баннер `.event-alert` и панель вылазки.

**Ограничение:** push-сервера нет; уведомление появляется, только пока открыта
игра. При закрытом браузере последствия рассчитываются при следующем запуске.

**Известные дефекты:** `notificationPermission` читается только при монтировании;
`notified.current` ставится до успешного `showNotification` (при ошибке
повторной попытки не будет); закрытие уведомлений не отменяется при быстрой
смене события; `postMessage` не проверяет origin/source.

## 6. PWA

| Параметр | Значение |
|---|---|
| `base` | `/StalkerTamagochi/` |
| `start_url`, `scope`, `id` | `/StalkerTamagochi/` |
| Режим | `standalone` |
| `registerType` | `prompt` |
| Service worker | `generateSW` (Workbox) |
| Offline | После первой полной загрузки |
| Precache | ~2,9 MiB, 32 записи, все уникальные |
| Fallback | `navigateFallback` на `index.html` |
| Обновление | `useRegisterSW`, кнопка «Обновить» → `updateServiceWorker(true)` |

Manifest: имя «ЗОНА — персональный КПК», короткое «ЗОНА», язык `ru`, иконки
192/512, `background_color #161a17`, `theme_color #202720`.

### Что попадает в кэш

Все `js/css/html/svg/png/webp/woff2/txt` из `dist`, включая шрифты, иконки,
карту, атлас предметов, слои персонажа, лицензии и `notification-handler.js`.
После чистки 20.11.2026: **32 записи, все уникальные, ~2,9 MiB**. Иконки
манифеста добавляются автоматически и исключены из glob-сканирования, чтобы не
дублироваться. `scene.webp` и `stalker.webp` остаются в `dist` как исходные
ассеты, но исключены из precache через `globIgnores`.

### Проблемы PWA

- Седьмое лицо теперь WebP (1024×1024, ~190 КБ) вместо PNG 1,47 МБ.
- `scene.webp` (268 КБ) и `stalker.webp` (232 КБ) не используются и не
  кэшируются, но всё ещё лежат в `dist`.
- Нет `screenshots`, `shortcuts`, `categories`, `orientation`.
- 512-иконка объявлена `any maskable` без отдельной safe zone.
- `apple-touch-icon` 192×192 вместо 180×180.
- Нет `color-scheme` и периодической проверки обновлений.

## 7. Установка

- `beforeinstallprompt` перехватывается, событие сохраняется в state.
- Кнопка «Установить КПК» вызывает `prompt()`, затем `userChoice`.
- Если события нет — открывается диалог с инструкциями для Android, iPhone,
  компьютера.
- `appinstalled` показывает toast.
- В standalone-режиме кнопка не скрывается и не проверяет, что приложение уже
  установлено.

## 8. Адаптивность

| Breakpoint | Что меняется |
|---|---|
| ≥ 1550 px | дополнительная ширина контейнера |
| ≤ 1150 px | сетки складываются в одну колонку |
| ≤ 820 px | карта выше, слоты экипировки перестраиваются |
| ≤ 540 px | мобильный режим: фиксированная нижняя навигация, корпус без рамки, две колонки карточек |
| ≤ 360 px | скрываются иконки в статах |

На мобильном навигация фиксируется снизу с `env(safe-area-inset-bottom)`;
`.workbench` получает верхний, боковые и нижний inset, чтобы контент не уходил
под системные элементы в standalone-PWA.

## 9. Доступность: что уже хорошо

- `lang="ru"`, `theme-color`, `viewport-fit=cover`.
- `button:focus-visible`, `:has(:focus-visible)` для лиц.
- `prefers-reduced-motion` отключает анимации и переходы.
- Нативные `<dialog>` с фокус-ловушкой браузера.
- `role="meter"` с `aria-valuenow/min/max`.
- `role="status"`/`aria-live` для нового сообщения.
- `role="img"` и осмысленный `aria-label` у портрета; декоративные слои
  `aria-hidden`; пустые `alt`.
- Радиогруппа лиц с `fieldset`/`legend`.
- Нижняя навигация и тост учитывают `safe-area-inset-bottom`.

## 10. Доступность: известный долг

| Проблема | Где | Что делать |
|---|---|---|
| Текст 5–9px | `style.css` | минимум 10–12px, лучше 12–14 |
| `aria-label` на `div`/`small` без роли | `App.tsx`, `MapViewport.tsx` | `role="group"` или убрать |
| Фокус теряется после открытия события | `App.tsx` | фокус на заголовок/первый вариант |
| Дубли `id="dialog-title"` | `App.tsx` | `useId()` |
| Тач-таргеты < 44px у текстовых кнопок | `style.css` | поднять `min-height`/padding |

**Исправлено 20.11.2026:** невидимая кнопка «Случайное имя», отключённый zoom,
тост под диалогом (портал в открытый `<dialog>`), обрезание длинного имени,
CTA ниже сгиба (закреплён на мобильном), верхний safe-area, контраст hover,
error boundary.

## 11. Правила UI-текста

- Язык — русский, обращение «ты», короткие фразы.
- Названия кнопок — глаголы: «Накормить», «Напоить», «Открыть карту».
- Не обещать фоновые push-уведомления: их нет.
- Не писать «всё сохранено», если `warning` активен.
- Числа и единицы — через `PACK_CAPACITY`, `EVENT_TIMEOUT`, `DAY`, а не
  хардкодом в тексте.
- Новые строки — в стиле существующих; не добавлять английские подписи.

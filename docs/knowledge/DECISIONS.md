# Решения и компромиссы (ADR)

**Сверено с кодом:** 20.11.2026.  
Это не исторические протоколы встреч, а зафиксированные решения, которые
видно в коде и документации. Если решение меняется — добавь новую запись и
пометь старую как заменённую.

---

## ADR-001. Статический SPA на GitHub Pages, без сервера

**Статус:** принято.

**Контекст:** прототип должен быть дешёвым, приватным и работать без
аккаунтов; push-уведомления и облачная синхронизация не входят в первый
прототип.

**Решение:** только статические файлы; хостинг — GitHub Pages; прогресс —
в `localStorage`; уведомления — локальные, пока открыта игра.

**Следствия:**

- нет серверной синхронизации, аккаунтов и фонового push;
- при закрытом браузере уведомления не приходят;
- время догоняется при следующем открытии;
- публикация — отдельный force-push в `gh-pages`.

**Пересмотреть, если:** появятся аккаунты, облачные сохранения, реальные
push-уведомления или необходимость скрыть игровую логику.

## ADR-002. Чистый reducer + localStorage вместо БД

**Статус:** принято.

**Контекст:** состояние маленькое (единицы килобайт), один игрок, офлайн —
обязателен.

**Решение:** `Game` — обычный JSON-объект; `reduceGame(prev, action, realNow)`
возвращает новое состояние; `useGame` читает/пишет `localStorage`.

**Следствия:**

- легко тестировать без браузера;
- можно воспроизвести любое состояние из JSON;
- нет транзакций, миграций «из коробки» и защиты от подмены;
- каждое действие — полная сериализация.

**Пересмотреть, если:** состояние вырастет до мегабайт, появятся несколько
устройств или конкурентные записи.

## ADR-003. Догон реального времени с сохранённым PRNG

**Статус:** принято.

**Контекст:** тамагочи живёт, пока браузер закрыт; при возвращении нужно
применить голод, ошибки, события, штрафы и прибытие в правильном порядке.

**Решение:** `applyTime` двигает `lastTick` по ближайшим границам; случайность
идёт через LCG с `seed` в сохранении; `Math.random()` в модели запрещён.

**Следствия:**

- закрытый браузер не теряет прогресс;
- результат не зависит от частоты тиков;
- нельзя менять порядок событий/формулы без миграции;
- «догон» может быть дорогим на длинных пропусках, но ограничен смертью
  (72 часа) и конечными событиями.

**Пересмотреть, если:** появится серверное время или фоновая симуляция.

## ADR-004. 15 минут на событие, 24/48/72 часа на уход

**Статус:** принято.

**Контекст:** нужен темп «проверяй игру несколько раз в день», но без
жестокости тамагочи 90-х.

**Решение:** событие ждёт 15 минут; первая ошибка ухода — через 24 часа,
вторая — через 48, смерть — через 72; одновременно пропущенные потребности
считаются одной шкалой.

**Следствия:**

- игрок может отсутствовать сутки без смерти;
- открытие события останавливает и штраф, и дорогу;
- опоздание ровно на 15:00 считается опозданием;
- после исправления ухода ошибки снимаются, но здоровье лечится отдельно.

**Пересмотреть, если:** появятся уведомления в фоне, режимы сложности или
«отпуск».

## ADR-005. Вместимость 50 кг, включая надетое

**Статус:** принято.

**Контекст:** нужен простой, понятный лимит, который заставляет выбирать
хабар и снаряжение.

**Решение:** `packWeight(inventory)` учитывает все предметы, включая надетые;
надетое не удаляется из рюкзака; покупка/лут/могила проверяют лимит.

**Следствия:**

- нельзя надеть броню «бесплатно»;
- частичный забор из могилы и с земли сохраняет остаток;
- запасную копию надетого типа нельзя продать/выбросить;
- `drop` в пути кладёт предмет в точку назначения (известная странность).

**Пересмотреть, если:** появится отдельный инвентарь экипировки или
транспорт.

## ADR-006. Один артефакт на поясе, четыре слота снаряжения

**Статус:** принято.

**Контекст:** артефакты должны быть выбором с побочным эффектом, а не
коллекцией пассивных бонусов.

**Решение:** `equipped: Artifact | null`; четыре слота (`suit`, `mask`,
`primary`, `secondary`); артефакт можно сменить/снять в любой момент, включая
путь; эффекты действуют и при закрытом КПК.

**Следствия:**

- нет стека артефактов;
- пистолет, куртка и детектор механически пусты;
- броня/противогаз/винтовка работают только в слоте;
- баланс артефактов сильно влияет на выживание.

**Пересмотреть, если:** появятся контейнеры, несколько слотов или ремонт.

## ADR-007. Слои персонажа вместо цельного портрета

**Статус:** принято.

**Контекст:** нужно показывать лицо, противогаз, куртку и комбинезон
независимо, без генерации комбинаций.

**Решение:** отдельные WebP-слои (тело, лицо/атлас, маска, куртка, броня) в
одной системе координат 1024×1536; фон локации — отдельный слой; одежда
определяется только `game.gear`.

**Следствия:**

- 6 лиц в атласе + отдельный PNG для седьмого;
- новые вещи требуют нового слоя и CSS-координат;
- вес ассетов растёт;
- легко добавить фон локации без перерисовки персонажа.

**Пересмотреть, если:** появится 3D/скелетная анимация или десятки лиц.

## ADR-008. Деплой через GitHub Actions

**Статус:** принято 25.11.2026; заменяет публикацию force-push в `gh-pages`.

**Контекст:** исходники переехали в Git-репозиторий
`regkriks-star/StalkerTamagochi`, аккаунт публикации сменился. Держать
отдельную одноразовую историю `gh-pages` больше не нужно.

**Решение:** `.github/workflows/deploy.yml` на push в `main` ставит
зависимости, собирает `npm run build` и публикует `dist` через
`actions/deploy-pages`. Pages работает с Source: GitHub Actions.

**Следствия:**

- деплой запускается пушем, а не отдельной командой;
- `dist/` и `gh-pages` не коммитятся;
- секреты не нужны, используется `GITHUB_TOKEN`;
- откат — `git revert` + push, история деплоев видна в Actions;
- старый `publish.mjs` удалён, чтобы не отправить сборку в недоступный
  `psyselfhelp`.

**Пересмотреть, если:** понадобится деплой на другой хостинг или отдельный
артефактный репозиторий.

## ADR-009. Node test runner + Playwright

**Статус:** принято, но под вопросом.

**Контекст:** нужны быстрые юнит-тесты без тяжёлого фреймворка и реальные
браузерные проверки PWA.

**Решение:** `scripts/test.mjs` компилирует модель локальным TypeScript в
`.tmp-tests` и запускает `node --test`; `@playwright/test` — для E2E;
`publish.test.mjs` — для публикации.

**Следствия:**

- нет зависимости от Vitest/Jest;
- тесты модели быстрые;
- встроенная поддержка TypeScript в Node не требуется;
- перед тестами есть шаг компиляции (~1 с);
- E2E требует браузера, preview и сборки;
- нет покрытия и репортинга из коробки.

**Пересмотреть, если:** CI начнёт падать на разных Node; тогда `tsx`/Vitest
или отдельный `tsconfig.test.json`.

## ADR-010. Русский интерфейс и «приборная» эстетика

**Статус:** принято.

**Контекст:** игра про постсоветскую Зону; аудитория — русскоязычная.

**Решение:** весь UI на русском, обращение «ты», Oswald для заголовков,
IBM Plex Sans для текста, тёмный оливково-янтарный КПК, нативные диалоги,
анимации только по делу.

**Следствия:**

- нет i18n;
- тексты — часть дизайна, их нельзя менять без проверки вёрстки;
- шрифты локальные (Fontsource), без CDN;
- часть подписей 5–9px — известный долг доступности.

**Пересмотреть, если:** появится английская аудитория или требование
локализации.

## ADR-011. Ограниченный стартовый набор и «необратимые» вещи

**Статус:** наблюдение, требует решения.

**Контекст:** стартовые ПМ, куртку и детектор можно продать, но в UI торговца
их нет; после продажи/потери вернуть их нельзя.

**Решение (фактическое):** так получилось; модель `buy` допускает покупку, но
список торговца их не содержит.

**Следствия:** игрок может навсегда лишиться предметов, которые считаются
базовыми.

**Пересмотреть:** добавить их в ассортимент или запретить продажу; решение
зафиксировать здесь и в `GAME-RULES.md`.

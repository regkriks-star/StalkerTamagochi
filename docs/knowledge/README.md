## Как дополнять базу

1. **Меняй документ вместе с кодом.** Не «потом»: отдельный PR с документацией
   почти всегда отстаёт.
2. **Обновляй дату сверки** в шапке этого файла и в профильном документе.
3. **Добавляй запись в [`CHANGELOG.md`](CHANGELOG.md)**: дата, что изменено,
   какие проверки прошли.
4. **Не дублируй таблицы целиком.** Полные таблицы предметов/событий живут
   только в [`GAME-RULES.md`](GAME-RULES.md). В остальных местах — ссылки.
5. **Ссылайся на файлы и символы, а не на номера строк.** Номера строк быстро
   устаревают; `parseSave`, `reduceGame`, `ITEMS` — стабильнее.
6. **Новый документ — новая строка в карте выше.** Иначе его не найдут.
7. **Не пиши секреты и локальные пути.** Оригиналы ассетов описывай как
   «внешний архив», без `/home/...`.
8. **Проверяй факты командой.** Для чисел — `src/game.ts` и тесты; для
   размеров — вывод `vite build`; для публикации — `dist` и живой сайт.
9. **Отмечай расхождения.** Если код и README расходятся, это баг; заведи
   задачу в [`BACKLOG.md`](BACKLOG.md), а не просто исправь текст.

## Известные ограничения самой базы

- Она создана по состоянию на 25.11.2026; живой сайт и `dist` могут быть новее.
- Идентификатор состояния — commit hash в GitHub; до первого push —
  дата и содержимое `dist/manifest.webmanifest`.
- E2E-результаты зависят от машины и таймаутов; на 20.11.2026 после исправлений
  прогон был 11/11, но на медленном раннере возможны таймауты.
- Полный `npm audit` в среде аудита не завершился; production-зависимости
  проверены отдельно.

Если сомневаешься, что важнее — этот файл или `src/game.ts`, — прав
`src/game.ts`. Но затем обнови этот файл.

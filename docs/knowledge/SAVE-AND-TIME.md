# Сохранения и время

**Сверено с кодом:** 20.11.2026.  
**Источник истины:** `Game`, `createGame`, `reduceGame`, `applyTime`,
`parseSave` в `src/game.ts`; `src/useGame.ts`.

## 1. Где и как хранится

| Параметр | Значение |
|---|---|
| Хранилище | `localStorage` браузера |
| Ключ | `zone-pda.save.v1` |
| Формат | JSON |
| Версия | 3 (`Game.version`) |
| Резервная копия повреждённого | `zone-pda.save.v1.corrupt` |
| Автосохранение | После каждого действия и каждого тика (раз в секунду) |
| Облако / аккаунт | Нет |
| Синхронизация вкладок | Через событие `storage`, без сервера |

Сохранение привязано к origin + браузеру. Очистка данных сайта удаляет
прогресс. Экспорт JSON есть в настройках; импорта нет (заявленное ограничение).

## 2. Структура `Game` v3

### Личность и мир

| Поле | Тип | Смысл |
|---|---|---|
| `version` | `3` | Версия формата |
| `face` | `number \| null` | Выбранное лицо; `null` — персонаж ещё не создан |
| `name` | `string` | Имя/позывной |
| `generation` | `number` | Номер жизни, с 1 |
| `location` | `LocationId` | Текущая локация |
| `seed` | `number` | Состояние PRNG (32 бита) |
| `startedAt` | `number` | Начало первой жизни; переживает поколения |
| `lastTick` | `number` | Игровое «сейчас» |
| `offset` | `number` | Накопленная ручная перемотка |
| `nextId` | `number` | Счётчик id для логов/могил |

### Состояние героя

| Поле | Смысл |
|---|---|
| `health`, `food`, `water`, `energy`, `radiation` | 0–100 |
| `rubles` | Деньги |
| `xp`, `raids`, `mistakes` | Опыт, число прибытий, ошибки ухода |
| `lastCare` | `{ food, water, rest }` — время последнего ухода |
| `inventory` | Все 14 предметов, включая нули |
| `gear` | `{ suit, mask, primary, secondary }` — id или `null` |
| `equipped` | Артефакт на поясе или `null` |
| `faction` | `Faction \| "loner" \| null` |
| `reputation` | По 4 фракциям |
| `inviteAt` | Время авто-выбора фракции или `null` |
| `dead` | Флаг смерти |

### Рейд

`raid: Raid | null`:

| Поле | Смысл |
|---|---|
| `location` | Цель |
| `origin` | Откуда вышли |
| `phase` | `travel`, `choice`, `return` |
| `startedAt`, `endsAt` | Границы текущей фазы |
| `event` | Индекс в `EVENTS` |
| `graveId` | Могила-цель или `null` |
| `startPosition` | Позиция на карте при смене маршрута (опционально) |
| `remainingMs` | Оставшееся время после события |
| `openedAt` | Когда открыли событие; `null` — ещё нет |

### Мир

| Поле | Смысл |
|---|---|
| `ground` | `Partial<Record<LocationId, Inventory>>` — вещи на земле |
| `searchedAt` | Время последнего поиска по локациям |
| `graves` | Тела: id, имя, поколение, время, локация, инвентарь, деньги |
| `memorials` | Погибшие: имя, поколение, время, причина, локация, XP |
| `log` | До 80 последних сообщений |

### Инвентарь

Ключи: `food`, `water`, `medkit`, `antirad`, `scrap`, `stone`, `spark`,
`moon`, `pistol`, `jacket`, `detector`, `mask`, `rifle`, `armor`.
Все значения — неотрицательные целые. Нули хранятся, чтобы форма была
предсказуемой.

## 3. Жизненный цикл

```text
localStorage
  → loadGame()
      → JSON.parse
      → parseSave() — миграции + валидация
          ├── null → сохранить raw в .corrupt, создать новую игру, warning
          └── Game → reduceGame(saved, tick) — догнать время
  → useState(initial)
  → useEffect: tick каждую секунду + visibilitychange + storage
  → send(action)
      → прочитать актуальный save (если lastTick >= текущего)
      → reduceGame(prev, action)
      → setGame(next)
      → localStorage.setItem(...)
```

Если `localStorage` недоступен (приватный режим, запрет, квота), `loadGame`
возвращает новую игру и warning; сессия работает в памяти, но не сохраняется.
Если запись не удалась, `useGame` выставляет warning, но игра продолжается.

## 4. Миграции

| Из | В | Что делает |
|---|---|---|
| v1 | v2 | `location = "camp"`, `gear` из инвентаря (armor/jacket/pistol), `ground = {}`, `searchedAt = {}`, `seed = startedAt >>> 0`, добавляет `mask`/`rifle` в инвентари, рейд: `origin = camp`, `remainingMs = 60_000`, `openedAt = null`, `event += 1`, для `choice` пересчитывает `endsAt = startedAt + 15 мин` |
| v2 | v3 | `face = 0` (первое лицо) |

После миграции `parseSave` валидирует **весь** объект. Неизвестная версия
отвергается. Если меняешь форму `Game`, добавь миграцию и подними версию;
иначе старые сохранения будут отвергнуты и игрок начнёт заново.

Важно: v1→v2 сдвигает индексы событий на +1, потому что в v1 не было события
бандитов. Не повторяй такие сдвиги без миграции.

## 5. Модель времени

- `lastTick` — игровое «сейчас».
- `offset` — сумма всех `skip`; сохраняется, поэтому перемотка необратима.
- `realNow` — параметр `reduceGame`; в браузере это `Date.now()`.
- Целевое время: `max(lastTick, realNow + offset)`. Часы назад не идут.
- `skip` применяется до `applyTime`; затем время догоняется.

### `applyTime(game, target)`

Цикл, пока `lastTick < target` и персонаж жив:

1. `oldestCare = min(lastCare.food, water, rest)`.
2. `nextMistake = oldestCare + (floor((lastTick − oldestCare)/DAY) + 1) × DAY`.
3. `end = max(lastTick, min(target, nextMistake, raid.endsAt, inviteAt))`.
   Если событие открыто (`choice` + `openedAt != null`), `raid.endsAt`
   игнорируется — дорога стоит.
4. За `hours = (end − lastTick)/3600000`:
   - еда/вода/силы уменьшаются;
   - артефакты дают эффекты;
   - радиация > 40 бьёт по здоровью;
   - `lastTick = end`.
5. Если достигнут срок ухода — новая ошибка, health −20, при 3 — смерть.
6. Если достигнут конец фазы рейда:
   - `travel` → `choice` на 15 минут;
   - `choice` → `missEvent` и продолжение;
   - `return` → прибытие, `raids++`, `xp+=20`, возможно приглашение.
7. Если достигнут `inviteAt` — авто-выбор фракции.

После цикла `lastTick = target` (даже если смерть наступила внутри — могила
получит время смерти, но `lastTick` уйдёт вперёд).

### Что это даёт

Закрытый браузер не выполняет таймеры, но при следующем открытии игра
рассчитывает всё пропущенное: голод, ошибки, события, штрафы, прибытие,
приглашение. Порядок событий детерминирован, потому что PRNG хранится в
`seed`.

## 6. Валидация `parseSave`

Проверяется:

- `version === 3`, `face` (null или валидный индекс), `name` (строка до 24
  символов), `dead` (boolean);
- целочисленность `generation`, `startedAt`, `lastTick`, `offset`, `rubles`,
  `xp`, `raids`, `mistakes`, `nextId`;
- `generation >= 1`, `mistakes <= 3`, `startedAt <= lastTick`;
- статы 0–100;
- полный инвентарь (все 14 ключей — целые неотрицательные);
- `lastCare` не в будущем;
- локация, seed ≤ 0xFFFFFFFF;
- слоты снаряжения совпадают с типом предмета и предмет есть в рюкзаке;
- `ground`/`searchedAt` — только известные локации;
- репутация, фракция, артефакт;
- `inviteAt` только при `xp >= 60`, без фракции, не в прошлом;
- рейд: известная локация, валидная фаза, таймеры, позиция 0–100, событие
  в диапазоне, могила;
- могилы/мемориалы/лог — правильная форма;
- `dead` несовместим с рейдом и приглашением;
- `face === null` несовместим со смертью, рейдом и приглашением.

Длина `name` ограничена 24 символами. Остальные пробелы: размер `log` не
ограничен, числовые поля не имеют верхней границы (кроме seed), `nextId` может
быть меньше существующих id. Это не критично для локальной игры, но при
импорте JSON стоит ужесточить.

## 7. Мультивкладочность

- `send` читает актуальное сохранение и берёт его, если
  `saved.lastTick >= previous.lastTick`. Так подхватываются чужие изменения.
- `storage`-обработчик применяет `saved`, только если его `lastTick` не старше
  текущего. Старые события больше не откатывают прогресс.
- Каждая вкладка всё ещё пишет в `localStorage` раз в секунду. Две вкладки
  создают поток `storage`-событий и лишние перерисовки. Долгосрочно —
  `BroadcastChannel`/Web Locks и запись только при изменении или раз в 5–10
  секунд.

## 8. Повреждённое сохранение

1. `JSON.parse`/`parseSave` вернули `null`.
2. Сырой JSON копируется в `zone-pda.save.v1.corrupt`.
3. Создаётся новая игра.
4. Показывается warning: «Сохранение повреждено… начата новая история».
5. Старое сохранение остаётся в `.corrupt` для ручного разбора.

Если `localStorage.setItem` для `.corrupt` тоже не сработал, срабатывает общий
`catch` и показывается предупреждение о запрете хранения.

## 9. Как посмотреть сохранение

В DevTools → Application → Local Storage → origin игры → ключ
`zone-pda.save.v1`. JSON можно скопировать в файл и сравнить с этим документом.
Экспорт из UI: «Настройки» → «Скачать» (JSON-файл). Импорт пока не реализован.
